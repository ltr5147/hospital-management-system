Design Memo

A tree fits the doctor reporting structure because it shows who reports to whom. The root represents the doctor at the top, and each child represents a direct report. This assignment uses a binary tree, so each doctor can have at most two direct reports. It is not a binary search tree because doctors are placed according to management relationships, not alphabetical order. I reject missing parents, invalid sides, duplicate names, and occupied positions so an insertion cannot accidentally replace an existing branch. A real system would use unique employee IDs and might allow more than two reports.

The three traversals visit the same doctors in different orders. Preorder visits a manager before their reports, which could help display a hierarchy from the top down. Inorder visits the left branch, the manager, and the right branch. It provides sorted output in a binary search tree, but does not sort this reporting tree. Postorder visits reports before their manager, which could help combine departmental results before preparing a manager's summary. Each traversal takes O(n) time and returns n names, with additional recursion space depending on the tree's height.

A min-heap lets emergency intake prioritize urgency instead of arrival order. The smallest urgency score stays at the root, so peek takes O(1) time. Heap repairs after insertion or removal take O(log n), keeping repeated updates efficient. Patients with equal urgency can leave in either order in this version; a real application could add arrival numbers to break ties fairly. Printing the heap shows its internal layout, not a fully sorted treatment list. Empty removals return None so the caller can handle an empty queue.
